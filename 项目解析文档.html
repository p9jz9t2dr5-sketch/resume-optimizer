一个面向求职者的 AI 简历优化 + 对话式模拟面试平台。本文档从「项目做什么、核心入口在哪、各代码模块负责什么、开发踩过哪些坑」四个维度，对当前仓库（commit b8b89c1）做一次完整拆解。

一、这个项目是做什么的

一句话定位：用户输入「自己的简历」+「目标岗位的 JD（职位描述）」，AI 帮你做三件事——① 评估简历与岗位的匹配度并给改进建议；② 润色简历文案；③ 开启一场针对该岗位的对话式模拟面试。

目标用户：正在求职、需要让简历更贴合目标岗位、并想在面试前做模拟训练的候选人。

核心产品闭环（5 步）

步骤用户动作AI 做的事技术实现
1. 注册 / 登录邮箱 + 密码签发 JWT，记录用户auth_service + bcrypt + JWT
2. 上传简历传 PDF / Word / 图片OCR / 解析成结构化文本file_parser（图片走 Qwen-VL）
3. 粘贴 JD粘贴岗位描述结构化抽取岗位要求llm_service（DeepSeek）
4. 匹配度分析点「分析」打匹配分 + 给出差距与建议resume_service + llm_service.analyze_match
5. 模拟面试开启对话按岗位追问、点评回答chat_service（SSE 流式）
产品边界已收敛：早期规划的「公司库」「面试助手」静态页已砍掉，当前只聚焦「对话式模拟面试」这一条主链路，保证每个功能都端到端可用。

七、一次完整请求的数据流

场景 A：简历匹配度分析

浏览器(page.tsx)
  → 上传简历 → POST /api/resumes/upload
       backend resumes.py → resume_service.upload_and_parse_resume()
         → file_parser.parse_file()  [图片→Qwen-VL / 文本→本地抽取]
         → 写入 resumes 表
  → 粘贴 JD → POST /api/jd/parse
       backend jd.py → llm_service（DeepSeek）结构化 JD
  → 点「分析」→ resume_service + llm_service.analyze_match()
         → anonymizer 脱敏 → DeepSeek 计算匹配分 + 建议
         → 返回分数 + 报告（前端 ScoreRing / MatchReport 渲染）

场景 B：对话式模拟面试（SSE 流式）

POST /api/chat/start            → chat_service.create_session() 建会话
POST /api/chat/{id}/message     → chat_service.stream_chat_response()
         → 读取简历 + JD 作为上下文
         → 调 DeepSeek（SSE 逐 token 返回）
         → 前端 chatStore 实时追加气泡，lib/api.ts 解析流

十、关键配置（.env 要填什么）

.env 已被 .gitignore 排除，不会进仓库。后端运行依赖以下变量：

变量用途缺失后果
DEEPSEEK_API_KEYDeepSeek 平台密钥（源）—
OPENAI_API_KEY实际被文字 AI 读取，需 = DeepSeek key文字链路 503/502
OPENAI_BASE_URL默认 https://api.deepseek.com/v1连错端点
DASHSCOPE_API_KEY百炼密钥，供 Qwen-VL 做图片 OCR图片简历无法解析
DATABASE_URLSQLite 或 PostgreSQL 连接串无法建库
JWT_SECRET签发/校验 JWT登录失效
CORS_ORIGINS / REDIS_URL跨域白名单 / 配额缓存CORS 报错 / 配额降级本地
⚠️ 安全提醒：API Key 属于敏感凭证，切勿明文贴在聊天框或提交进仓库。本仓库已通过 .gitignore 排除 .env，部署时由服务器本地维护。
